## Q1 — Scripting today: is there user scripting, in what language, how is it wired?

### Takeaway
Yes. PH2D already ships a working **Luau** gameplay-scripting pipeline: crate `ph2d-script` (mlua 0.12, `luau` feature, sandboxed VM, content-hash hot reload), a `LuauScript` component (a **file path** + per-object overrides) attachable to any object via the Inspector's "Add Component → Script → Browse", three hooks (`init`/`update`/`on_signal`), and an Inspector "Script" section that renders `ph2d.property(...)` declarations as controls. **The script text itself is edited in an EXTERNAL editor** — the plan that shipped this explicitly put "Editor de texto dentro do app" OUT of scope, so the CodeEditor line reverses a written decision and must say so.

### Inferences
- The CodeEditor's primary consumer already exists: a `.luau` file referenced by `LuauScript.source`. The cheapest high-value integration is "open the attached script in-app" from the Inspector Script section (a new `ScriptFieldEdit`-like action next to `Browse`), with save → existing mtime/blake3 hot reload doing the rest (no runtime change needed).
- Diagnostics in an editor need line/column; today's `ModuleError` strings drop everything after line 1 — the editor line will need a structured error type in `ph2d-script` (non-frozen crate, additive).
- Because the plan doc 13 §3.9 recorded the opposite decision, the new line's ADR must cite and supersede that row (repo rule: "O que foi MEDIDO e REJEITADO não se reconstrói" — CLAUDE.md §5.0; here it was a scope exclusion, not a measured refusal).

### Gaps
- Whether Luau's type checker/analyzer is reachable through mlua 0.12 (only compiler+VM are evident in the repo); `--!strict` checking is not run anywhere in production code (see Q8).
- No `require` binding found in `ph2d-script` (grep of `require` in src hits only comments) — multi-file modules/libraries for user scripts appear unsupported; not verified by running.

## Q2 — Other authored-behaviour languages: expressions, Motion, Timeline, Macros, Components, blocks

### Takeaway
Besides Luau there is ONE textual mini-language: **VEX-lite** expressions (`ph2d-expr-parse` → frozen `ph2d_expr::Expr` IR), shared by the Timeline expression lane and the Motion `motion.expression` node. Game components (vida, navegação, câmera, HUD, state machine…) are authored as **Inspector cards**, not code. Macros record resolved commands, not text. ADR-0036 planned blocks + node-programming that compile DOWN to Luau (not built).

### Cited Findings
- `ph2d-expr`: shared per-element compute IR (Houdini VEX/Blender field analogue), lowerings to CPU eval and WGSL; "Luau lowering: lands with the gameplay domain"; **FROZEN at W2.T4 (ADR-0039)** — [crates/ph2d-expr/src/lib.rs:1-27](crates/ph2d-expr/src/lib.rs#L1).
- `ph2d-expr-parse`: hand-written recursive-descent "VEX-lite" parser, text → frozen IR; "This is the ONE parser (ADR-0144)", lives in a leaf crate so the grammar can grow without touching the frozen IR — [crates/ph2d-expr-parse/src/lib.rs:1-15](crates/ph2d-expr-parse/src/lib.rs#L1).
- Motion: `motion.expression` node, formula is a TEXT param stored in the graph's additive string channel (`Graph::set_text_param`), NodeManifest stays f32-only (no contract bump); variables `i n t f x y a b c d`; parse error → zero field + node badge — [crates/ph2d-node-motion-expression/src/lib.rs:1-25](crates/ph2d-node-motion-expression/src/lib.rs#L1). Text params edited via card params (`node_text_param_overrides`) — [crates/ph2d-app-motion/src/motion_bridge_card_params.rs:61](crates/ph2d-app-motion/src/motion_bridge_card_params.rs#L61).
- Timeline expressions: ADR-0144 (frozen IR, separate post-composition pass, `time*100`, `wiggle(3,20)`, links to `Name.prop`) — [docs/architecture/decisions/0144-timeline-expressions-frozen-ir-separate-post-composition-pass.md:1-25](docs/architecture/decisions/0144-timeline-expressions-frozen-ir-separate-post-composition-pass.md#L1); follow-ups ADR-0151/0152 (per-clip, first-class lane source).
- Macros: `ph2d-macro` records timed tracks of events whose payload is bytes encoded by the owning family; never reads the wall clock (gate `the_macro_core_never_reads_the_wall_clock`) — [crates/ph2d-macro/src/lib.rs:1-12](crates/ph2d-macro/src/lib.rs#L1); ADR-0186. CLAUDE.md §5.1 says "Ainda sem UI nem Play em cena".
- ADR-0036 (Accepted, "implementação pendente"): blocks (`ph2d-blocks`, authoring-time) and node-programming both compile to Luau/bytecode; "Compilador fora do runtime" — [docs/architecture/decisions/0036-gameplay-authoring-blocks-and-nodes.md:1-36](docs/architecture/decisions/0036-gameplay-authoring-blocks-and-nodes.md#L1). No `ph2d-blocks` crate exists (`ls crates`).
- Game components are authored by edit structs in editor-core (`hud_edits.rs`, `nav_edits.rs`, `statemachine_edits.rs`, `counter_watch_edits.rs`, `macro_edits.rs`, …) — directory listing of [crates/ph2d-editor-core/src/](crates/ph2d-editor-core/src/); tutorials as PDFs `01_maquina_de_estados.pdf`, `02_vida_e_dano.pdf`, `03_navegacao.pdf` — [docs/Components/tutoriais/](docs/Components/tutoriais/).
- Other docs mentioning scripting: `docs/scripting/examples/spike/{llm-tests,lsp,debug-autonomy}/*.luau` (spike-era API), `docs/scripting/mcp/`, `docs/Vector Module/09_scripting_mcp.md`, and the Godot probes `docs/Components/ferramentas/godot_*.gd` (grep `-i "script|luau"` over docs).

### Inferences
- A code editor could serve VEX-lite too (one-line/short formulas) but the payoff is Luau; VEX-lite text lives in tiny TextInputs today. Syntax highlighting for both grammars could share a tokenizer interface, but the VEX-lite parser is the single source of truth for that grammar (ADR-0144) — highlighting must reuse it, not fork it.

### Gaps
- No doc found that plans an in-app code editor besides the 2026-05 design mock (Q3/Q10). `grep -i "code editor|editor de código|CodeEditor|GDScript"` hits only Godot research docs and UI research, not a plan.

## Q3 — Text infrastructure: widgets, layout, fonts, caret/selection, clipboard, IME

### Takeaway
There is a parley-based text stack, a single-line `TextInput` and a multi-line `TextArea` widget (simple, ≤500-LOC widgets), and one real rich-text editor (the Board's `TextEdit`, using parley `Cursor`/`Selection` with word/line/grapheme/bidi moves). **No monospace font is bundled** (token says JetBrains Mono but only Inter/Noto/Atkinson/Virgil TTFs ship), **IME pre-edit is ignored** (only `Ime::Commit`), clipboard is `arboard`. Nothing approaches a code-editor buffer (rope, line index, virtualization, gutter, highlighting).

### Cited Findings
- `ph2d-text` wraps parley (`TextSystem` owns `FontContext`+`LayoutContext`), dep `parley = "0.11.1"` — [crates/ph2d-text/src/lib.rs:1-20](crates/ph2d-text/src/lib.rs#L1); [crates/ph2d-text/Cargo.toml](crates/ph2d-text/Cargo.toml). Shaped-layout cache keyed by (text,size,wrap,weight,spacing) in a `BTreeMap` with a measured cap — [crates/ph2d-text/src/layout_cache.rs:1-12](crates/ph2d-text/src/layout_cache.rs#L1). Only three crates depend on parley directly: `ph2d-text`, `ph2d-board-layout`, `ph2d-imageio-svg` (grep of Cargo.toml).
- Bundled fonts: `InterVariable.ttf`, `NotoSansVariable.ttf`, `AtkinsonHyperlegibleNextVariable.ttf`, `Virgil-Regular.ttf` — [crates/ph2d-text/src/bundled.rs:19-47](crates/ph2d-text/src/bundled.rs#L19); `crates/ph2d-text/fonts/` contains no mono font. Token `FONT_MONO = "'JetBrains Mono', ui-monospace, 'SF Mono', Menlo, monospace"` — [crates/ph2d-tokens/src/typography.rs:131](crates/ph2d-tokens/src/typography.rs#L131).

### Inferences
- A code editor must bring: a mono font (bundling one is a `ph2d-text` foundational edit + licence entry in THIRD_PARTY_LICENSES.md, and `no_tofu_glyphs` implications), a buffer model (rope/line index), virtualized painting of only visible lines (layout cache cap was measured — thousands of lines per frame would stress it), IME pre-edit (shell-level, benefits all text fields), and a highlighter. The Board `TextEdit` is the best in-repo precedent for parley-cursor-based editing; parley's `PlainEditor` (single style) is plausibly closer to a code buffer's needs than the Board one, but per-token colouring needs multiple styles.

### Gaps
- Whether `TextInput` now supports selection/IME beyond the stale header — not traced through `interaction/state` (TextInputState users listed in Q4).

## Q4 — Widget/panel system, panel registration, family-crate pattern, shell ratchet, UI canon

### Takeaway
UI is retained-mode (`WidgetStore` keyed by AccessKit `NodeId`), painted with Vello through `ph2d-editor-core`. A new panel is a `ph2d-panel-<slug>` crate implementing the `Panel` trait, registered by codegen (`cargo run -p ph2d-panel-sync`); family logic goes in `crates/ph2d-app-<family>` talking to the shell through the 5-method `AppHost` trait; the shell has a hard LOC ratchet (189 041). Zero hex / zero f32 UI literal / zero hardcoded strings are build-breaking gates.

### Cited Findings
- ADR-0024 chose a retained model: `WidgetStore` = `BTreeMap<NodeId, InteractiveState>`, AccessKit `NodeId` is the widget identity, focus chain, keyboard accessibility (WCAG 2.1.1), MCP-queryable widget state; immediate-mode (egui-style) rejected — [docs/architecture/decisions/0024-editor-input-and-widget-state.md:35-102](docs/architecture/decisions/0024-editor-input-and-widget-state.md#L35).
- `Panel` trait: `type State`, `const ID`, `DEFAULT_VISIBLE`, `TITLE: TextKey`, `ICON: IconId`, `DEFAULT_SLOT`, `fn paint(state, ctx)`, `fn apply_event(...)`, `fn populate(store)` — [crates/ph2d-editor-core/src/panel/panel_trait.rs:24-148](crates/ph2d-editor-core/src/panel/panel_trait.rs#L24).
- `panel_seam!` macro generates `populate` + `apply_event` for thin forwarder panels only; complex panels keep explicit `event.rs` — [crates/ph2d-editor-core/src/panel/seam_macro.rs:1-65](crates/ph2d-editor-core/src/panel/seam_macro.rs#L1).
- New-panel recipe (DIRETRIZ §3.B.1), summarised: (1) slug, `DEFAULT_VISIBLE`, feature `panel-<slug>`; (2) crate with deps editor-core/a11y/tokens/text/vector/tool-registry; (3) `impl Panel` stub (template `ph2d-panel-inspector`); (4) `cargo run -p ph2d-panel-sync` regenerates feature, optional dep and `reg.push` in `ph2d-panel-registry-init` (never hand-edit between markers); (5) shell feature-proxy + `default` entry (gate `every_panel_the_registry_ships_reaches_the_binary`); (6) `ICON` (new `IconId` + `docs/design/icons/<slug>.svg`) and `DEFAULT_SLOT`, control ids in the panel crate's own `src/ids.rs`; (7) add to `PANEL_Z_ORDER_FALLBACK` (gate `architecture_every_panel_is_painted`); (8) if it scrolls, add to `cursor_over_hero_panel` in `forwarding.rs` (wheel gates); (9) check + `cargo test -p ph2d-panel-registry-init`; gates live in `tests/it/` (a `--bins` run doesn't reach them) — [docs/IntegracaoMultiAgente/DIRETRIZ.md:741-755](docs/IntegracaoMultiAgente/DIRETRIZ.md#L741). ## Q5 — Object/mode model, Hierarchy, Inspector, components: where would a "Script" live?

### Takeaway

## Q6 — Project format, schema, undo, file watching: how would script files be saved?

### Takeaway
A project is `(PROJECT_SCHEMA, ProjectFile)` in postcard; `PROJECT_SCHEMA = 189` on `main`, counted (never chosen) against the merge-base. Module documents with their own undo live as separate `ProjectFile` fields (Motion = text, Timeline = versioned postcard blob). Scripts are currently NOT embedded — only the path in the component travels. Global undo is snapshot-diff of `ProjectState` per frame; text edits inside a code editor would need their own undo (like Motion/Timeline). A `notify`-based `AssetWatcher` exists but is unused; scripts reload by polling `(len, mtime)` + blake3.

### Cited Findings
- `ProjectFile` fields: `state: ProjectState`, `assets`, `painted`, `motion: String` (canonical text, "diffável e mergeável por linha", own undo `MotionHistory`, kept out of ProjectState so Ctrl+Z of the canvas doesn't rewind the graph), `timeline: Vec<u8>` (postcard `TimelineDoc`, own undo), `physics`, `tokens`, `settings`, `player_tape`, `sprite_pixels`, `stable_id_counter` — [shells/desktop/src/project.rs:1-135](shells/desktop/src/project.rs#L18).
- `pub(crate) const PROJECT_SCHEMA: u32 = 189;` with the "escada" of steps beside it; "o valor se CONTA contra o `main` do dia, nunca se escolhe" — [shells/desktop/src/project_schema.rs:1-17,450](shells/desktop/src/project_schema.rs#L450). Recount tool: `python3 scripts/schema-recount.py` (CLAUDE.md §1 table).
- Script wave cost: `PROJECT_SCHEMA +1` only because the registrar entered the boot (no new type) — [docs/Components/handoffs/HANDOFF_INTEGRACAO_line_components_SCRIPT_2026-09-16.md:24](docs/Components/handoffs/HANDOFF_INTEGRACAO_line_components_SCRIPT_2026-09-16.md#L24).
- Undo: global, snapshot-based, "Registro por DIFF, não por gesto" (`post_frame_undo` compares state to baseline once per frame); scope = objects, hierarchy, canvas; panels have their own undo — [shells/desktop/src/undo.rs:1-17](shells/desktop/src/undo.rs#L1). `LuauScript.own` is a `BTreeMap` because "a captura é a unidade do undo e do save" (component.rs:44-47).
- File watching: `ph2d-asset` depends on `notify = "8"` ("Off-thread file watcher … inotify on Linux") — [crates/ph2d-asset/Cargo.toml:26-29](crates/ph2d-asset/Cargo.toml#L26); `AssetWatcher::watch_dir`, `drain`, `drain_blocking` — [crates/ph2d-asset/src/watcher.rs:55-116](crates/ph2d-asset/src/watcher.rs#L55). Grep for `AssetWatcher|watcher::` outside `ph2d-asset` finds no users.
- Script reload: `refresh` reads `fs::metadata` → `Stamp { len, modified }`, re-reads only if stamp changed, reloads only if content changed — [crates/ph2d-script/src/scene.rs:303-320](crates/ph2d-script/src/scene.rs#L303).
- HR-14: every saved struct versioned with pure `migrate_vN_to_vN+1` — [SKILL_Stack_PH2D_Definitiva.md:461-464](SKILL_Stack_PH2D_Definitiva.md#L461).

### Inferences
- If the editor writes the `.luau` file to disk, no schema change is needed and the existing reload path works (an in-app save could also call the reload directly to beat mtime granularity — open item 6 of the script handoff). Embedding scripts in the project (a `scripts` text field like `motion`, or an asset kind) is a schema step and a product decision (portability vs. external-editor workflow).
- Editor text undo should be per-document (like `MotionHistory`), not the global `ProjectState` diff — otherwise every keystroke diff would be a world snapshot comparison.

### Gaps
- Not determined where/if the project folder is defined (relative script paths vs absolute); `LuauScript::at("/tmp/bob.luau")` in tests suggests absolute paths are accepted.

## Q7 — Runtime: signals, play mode, determinism, hot reload, live values

### Takeaway
Scripts run when the timeline clock plays (no separate "Play mode" process); determinism rules are strict (BTreeMap, StableId order, fixed step, one update per tick, no wall clock). Signals go through `ph2d-runtime`'s double-buffered outbox (`SignalOrigin::Script` via `ph2d.emit`). Hot reload is content-addressed and preserves `self`. Live debugging is limited to the Inspector showing resolved values, failure reason and "clock playing" — no debugger, breakpoints, watch, or console panel exists.

### Cited Findings
- `ph2d-runtime`: one outbox, N consumers each with own cursor; double-buffered like Bevy `Events`; explains why `ph2d-script::MessageBus` (handlers inside) has had zero consumers — [crates/ph2d-runtime/src/lib.rs:1-40](crates/ph2d-runtime/src/lib.rs#L1).
- Run gate = `playhead.is_playing()`; `sync` runs when paused too (to feed declarations to the panel) — [crates/ph2d-app-components/src/script_bridge.rs:6-9](crates/ph2d-app-components/src/script_bridge.rs#L6).
- Determinism: StableId ordering (HR-5), fixed step, queued writes, `BTreeMap` — [crates/ph2d-script/src/scene.rs:12-30](crates/ph2d-script/src/scene.rs#L12); ADR-0022 "no HashMap in simulation" (filename in decisions/); libm transcendentals may diverge cross-OS (handoff §9.5).
- ADR-0019: cross-platform replay hash identical on Linux/macOS/Windows; hot reload deterministic 100/100, 0.31 ms p99 freeze; GC p99 0.005 ms — [docs/architecture/decisions/0019-spike-scripting-output.md:30-46](docs/architecture/decisions/0019-spike-scripting-output.md#L30).
- Live info available to UI: `InspectorScriptInfo { status, props (resolved, with origin), orphans, kept, failure: Option<String>, clock_playing, also_physics }` — [crates/ph2d-editor-core/src/script_edits.rs:112-133](crates/ph2d-editor-core/src/script_edits.rs#L112). Lua `print` in the placeholder goes to stdout (integration.rs:124-135).
- A console panel was designed (`11-console.html`, "log + Luau errors + assertions") but there is no `ph2d-panel-console` crate (ls crates; [docs/design/PROMPT_CLAUDE_DESIGN.md:159](docs/design/PROMPT_CLAUDE_DESIGN.md#L159)). Relevant memory: "Recusa que só o TERMINAL vê é um botão mudo" (project-memory index, feedback_a_refusal_only_the_terminal_sees.md).
- HR-7: editor and game are the same binary with feature flag `editor`; release game cuts editor code — [SKILL_Stack_PH2D_Definitiva.md:411-415](SKILL_Stack_PH2D_Definitiva.md#L411).

### Inferences
- A code editor's "run" is "save → hot reload while the clock plays", not a separate run target; the editor UI must therefore surface per-object `failure` and the VM's `Broken(msg)` in-place (gutter/problems list), and route `print` to a visible log (otherwise it violates the "terminal-only refusal" lesson).
- HR-7 implies the editor code must sit behind the `editor` feature (or in crates not linked into release-game).

### Gaps
- No live inspection of `self` tables (the VM state) is exposed; whether `SceneScripts` can enumerate `self` contents for a Watch panel was not checked.
