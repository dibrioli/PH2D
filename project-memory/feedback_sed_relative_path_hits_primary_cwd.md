O `cd` dentro de um comando composto do Bash **pode não ter efeito** (o sandbox roda a partir do *primary working directory*). Um `sed -i`/`>`/`mv` com **caminho relativo** então grava no repo ERRADO. Em Modo L isso significa: você acha que está no worktree da sua linha e escreve no `main`.

Aconteceu 2026-07-09 (linha `line/audio`): `cd crates/ph2d-panel-audio-editor/src && sed -i 's/HitIndex/ClippedHits/' paint.rs` editou `/home/enio/Documentos/Projetos/PH2D/crates/.../paint.rs` (o main). A **pista** foi o `ugrep: warning: paint_fx.rs: No such file` no mesmo comando — `paint_fx.rs` só existe na minha linha, então o cwd não era o worktree. Um `pwd` isolado depois mentiu (mostrou o worktree).

**Reset pós-/compact (2026-07-11, linha `line/MotionNodes`):** o cwd do Bash **reseta pro primary** (`/home/.../PH2D`, branch `main`) no começo de um turno após `/compact` — mesmo que o cwd tivesse persistido como worktree no turno anterior. A pista dessa vez: `rg strobe crates` e `git ls-files 'crates/ph2d-node-motion-*'` "sumiam" com crates que EU tinha commitado (strobe/drive) — porque estavam no worktree, não no main. Confirmei com `git rev-parse --show-toplevel` (deu o primary) + `git -C <worktree> log` (linha íntegra) + `git -C <primary> log` (main intocado). Detalhe útil: **dentro de um turno, `cd <worktree> && ...` PERSISTE** pros comandos seguintes (então um `git status` sem `cd` depois já mostra o worktree) — o reset é só na fronteira de contexto. Todos os comandos até eu perceber eram read-only → zero dano.

**Path absoluto NÃO basta — tem que ser o path da WORKTREE (2026-07-11, linha `line/Vector`):** o worktree fica **aninhado sob** o primário (`~/Documentos/Projetos/PH2D/Worktrees/line-Vector/`), então qualquer path absoluto que comece em `~/Documentos/Projetos/PH2D/shells/...` **sem** o segmento `/Worktrees/line-Vector/` atinge o **main**, não a linha. Aconteceu com as ferramentas `Read`/`Edit`/`Write` (não só shell): li e editei `.../PH2D/shells/desktop/src/render_loop/mod.rs` (o main) o tempo todo achando que era a worktree. As **pistas**: (a) `git status` da worktree **vazio** depois de 3 edições; (b) `cargo check -p` "Finished in 0.15s" **sem recompilar** um módulo que eu tinha acabado de adicionar — porque rodou contra uma árvore que eu não mexi. Zero dano porque a base era idêntica (linha recém-preparada sobre o main) e reverti: `cp` primário→worktree dos 3 arquivos, depois `git -C <primário> restore <meus tracked>` + `rm <meu untracked>`. **A orientação "prefira Edit/Write, exigem path absoluto" é exatamente a armadilha:** Edit/Write escrevem fielmente onde o path absoluto mandar — e o path do primário resolve.

**Why:** `cd` em compound command é intercept-ável; e um `sed -i` não falha quando o caminho relativo *casualmente existe* no outro repo — ele só corrompe silenciosamente. `git status` do worktree fica limpo, então nada avisa. E como o worktree é subdiretório do primário, o path absoluto do primário é um path VÁLIDO que existe — nunca dá erro.

**How to apply:** (0) **em Modo L, o path canônico é o da WORKTREE** — `.../PH2D/Worktrees/line-<módulo>/...`; monte todo path (Read/Edit/Write/shell) a partir da raiz da worktree, NUNCA de `.../PH2D/` direto (esse é o main). Guarde a raiz num var (`W=~/Documentos/Projetos/PH2D/Worktrees/line-<módulo>`) e prefixe. Path absoluto do primário é VÁLIDO e silencioso — só o segmento `/Worktrees/line-X/` te separa do main; (1) toda mutação de arquivo por shell usa **caminho absoluto da worktree**, nunca relativo + `cd`; (2) Edit/Write exigem path absoluto mas NÃO te protegem do tree errado — confira o `/Worktrees/` no path antes; após qualquer bloco de edições, `git -C <worktree> status` DEVE mostrar suas mudanças (vazio = você editou o main); (3) se um comando reclamar de um arquivo que você SABE que existe na sua linha, pare — o cwd está errado, não o arquivo; (4) rode `git -C <main> status` ao suspeitar, e reverta só o que você sujou (`git checkout -- <arquivo>` depois de conferir o diff); (5) **no 1º Bash de um turno pós-/compact numa jornada Modo L, assuma cwd=primary** — abra com `cd <worktree> && ...` (persiste no turno) e, antes de qualquer git/cargo/mutação, `test "$(git branch --show-current)" = "<linha>"` como fence.
