# Taxonomia e convenções

## Frontmatter obrigatório

Toda nota abre com **exatamente** estes campos, nesta ordem:

```yaml
---
titulo: "Frase curta, em português, sem numeração"
tags: [modulo/3d, tipo/<…>, assunto/<…>, status/<…>]
status: rascunho | proposto | aceito | obsoleto
modulo: 3D
atualizado: AAAA-MM-DD
resumo: "UMA frase: o que esta nota responde. É o que a LLM lê para decidir se abre o arquivo."
relacionados: ["[[nota-a]]", "[[nota-b]]"]
---
```

⚠️ **O campo `resumo` é a afordância central para LLM.** Ele é o que permite decidir o que ler sem ler.
Nota sem `resumo` útil é nota que será aberta à toa ou ignorada por engano.

## Taxonomia de tags (fechada — não invente tag nova sem atualizar esta nota)

### `tipo/` — o que a nota É

| Tag | Uso |
|---|---|
| `tipo/moc` | mapa de conteúdo, porta de entrada |
| `tipo/indice` | índice navegável |
| `tipo/visao` | por que algo existe; objetivos |
| `tipo/decisao` | uma escolha foi feita, com alternativas e preço |
| `tipo/referencia` | descrição estável de como algo funciona |
| `tipo/pesquisa` | levantamento externo, com fontes |
| `tipo/plano` | ordem de execução, waves, riscos |
| `tipo/prompt` | texto destinado a ser entregue a uma LLM |
| `tipo/meta` | sobre o cofre em si |

### `assunto/` — sobre o que a nota FALA

`arquitetura` · `crates` · `removivel` · `runtime` · `integracao` · `ferramenta` · `pincel` ·
`primitiva` · `zsphere` · `topologia` · `shading` · `pbr` · `sss` · `2d` · `matematica` ·
`performance` · `risco` · `waves` · `objetivos` · `benchmark` · `porte` · `taxonomia` · `especificacao`

### `status/` — confiabilidade

| Tag | Significa |
|---|---|
| `status/rascunho` | em escrita, não confie |
| `status/proposto` | escrito, aguarda decisão do Enio |
| `status/aceito` | decidido; mudar exige nota nova ou emenda datada |
| `status/obsoleto` | **mantido para história**; o cabeçalho aponta a substituta |

⚠️ **Nunca apague uma nota obsoleta em silêncio.** Marque `status/obsoleto` e aponte a substituta.
Uma nota que some leva junto o *porquê* de uma decisão, e a próxima LLM reconstrói o erro.

## Nome de arquivo

```
<pasta NN-Nome>/<NN.M>-<Titulo-Em-Kebab-Case>.md
```

- prefixo numérico ⇒ ordem estável no explorador e no índice;
- sem acento e sem espaço no nome do arquivo (o acento vai no `titulo:`);
- o número **nunca é reciclado**: nota removida deixa o número vago.

## Regras de escrita (herdadas do repositório)

Estas não são estilo — são as leis que o `CLAUDE.md` já cobra do resto do projeto:

1. **Nenhum número sem medição ao lado.** Se um teto aparece numa nota, a tabela que o produziu aparece
   junto, ou a nota diz explicitamente *"a medir"*.
2. **Comentário velho mente.** Ao mudar uma decisão, **edite a nota que a afirmava** — não acrescente
   uma segunda que a contradiga em silêncio.
3. **Cerca de Chesterton.** Ao registrar algo recusado, escreva **por que** foi recusado. *"Não fizemos
   X"* sem motivo faz a próxima LLM fazer X.
4. **Uma pergunta, uma porta.** Se dois lugares respondem a mesma coisa, um deles está errado e ninguém
   sabe qual.
5. **Português direto.** Recomendação primeiro, justificativa depois.

## Como uma LLM deve usar este cofre

```
1. leia 00-INDEX.md            → decida quais notas importam
2. leia os `resumo:` do frontmatter das candidatas
3. abra só as necessárias
4. ao terminar a tarefa, ATUALIZE `atualizado:` e o 00-INDEX se criou/moveu nota
```

## Fora do cofre, mas obrigatório

O cofre vive dentro do repositório da PH2D e **não** substitui:

- [`CLAUDE.md`](../../../CLAUDE.md) — os inegociáveis e o roteador por tarefa;
- [`SKILL_Stack_PH2D_Definitiva.md`](../../../SKILL_Stack_PH2D_Definitiva.md) — as Hard Rules;
- [`docs/architecture/decisions/`](../../architecture/decisions/) — os ADRs, que continuam sendo o
  registro formal de decisão do projeto inteiro.

> **Regra de fronteira:** decisão que afeta **só** o módulo 3D mora aqui. Decisão que toca contrato,
> schema ou outra linha vira **ADR** lá fora, e a nota daqui aponta para ele.
