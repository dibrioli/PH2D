# Contrato de porte para Rust + wgpu

## Por que o MVP é web, e por que isso não é desperdício

O pedido foi *"HTML e WEBGL para depois ser portado para Rust WGPU"*. A recomendação, com uma correção:

> **WebGPU, não WebGL.**

| | WebGL 2 | **WebGPU** |
|---|---|---|
| Compute shaders | ❌ não existem | ✅ |
| Storage buffers | ❌ | ✅ |
| Linguagem | GLSL ES | **WGSL — a mesma do `wgpu`** |
| Porte dos shaders | reescrita total | **cópia de arquivo** |

Com WebGL o motor de escultura teria de ser escrito **duas vezes** (hacks de *transform feedback* na
web, compute em Rust), e o protótipo não provaria a performance que é metade do objetivo. Com WebGPU,
**os `.wgsl` do MVP são literalmente os arquivos de produção**.

WebGPU está disponível por padrão em Chrome/Edge 113+, Firefox 141+ (Windows) / 145+ (macOS Apple
Silicon) e Safari 26 — é *Baseline* em 2026. O `wgpu` da PH2D está na **versão 28**.

## O que atravessa (escreva com carinho)

| Artefato do MVP | Destino em Rust |
|---|---|
| `src/shaders/*.wgsl` | `ph2d-sculpt3d-gpu` e `ph2d-mesh-render` — **verbatim** |
| layouts de buffer e uniforms | `#[repr(C)]` + `bytemuck::Pod` |
| matemática dos verbos | `ph2d-sculpt3d` |
| a lei do traço + tabela de falloff | `ph2d-sculpt3d` |
| grade espacial, adjacência CSR | `ph2d-mesh` |
| remesh, surface nets, QEM, multires | `ph2d-mesh` / `ph2d-sdf` |
| formato `.ph2ds` | leitor Rust, tradução direta |
| os 8 gates | testes Rust, **mesmos oráculos** |
| as 7 sondas | `tests/measure_*.rs`, o padrão da casa |

## O que fica para trás (não invista)

`app/` · `ui/` · `input/` · CSS · `vite` · qualquer coisa que toque `document`.

Na PH2D a UI é Vello sobre `ph2d-editor`, com tokens, i18n e o `WidgetStore` — nada da UI web
sobrevive, e isso **é o plano**. Não gaste tempo fazendo a UI web bonita; gaste fazendo-a *rápida de
mexer*.

## As cinco regras que protegem o porte

1. **Nenhuma extensão WebGPU sem equivalente documentado em `wgpu 28`.** Se precisar de uma, escreva o
   equivalente no comentário antes de usar.
2. **Nenhum atômico em `f32`.** Não existe em WGSL padrão, e o determinismo o proíbe. Use *gather* por
   adjacência CSR, ou ponto fixo em `atomic<i32>` com o fator documentado.
3. **Alinhamento explícito e comentado em todo uniform.** As regras de `std140`/`std430` são a armadilha
   silenciosa clássica entre JavaScript e Rust: o código "funciona" com valores errados.
4. **Nenhuma dependência do layout de memória do JavaScript.** Nada de `ArrayBuffer` compartilhado com
   suposição de padding; escreva serialização explícita.
5. **Cada `.wgsl` abre com um comentário nomeando a crate Rust que vai hospedá-lo.** Um arquivo sem dono
   é um arquivo que ninguém porta.

## O que o MVP tem de PROVAR antes do port começar

O port só é autorizado quando o `MEDICOES.md` responder, **com números reais**:

- [ ] o kernel de pincel é sub-milissegundo para 10⁶ vértices afetados?
- [ ] o traço é **independente do espaçamento** (gate 3 verde)?
- [ ] o voxel remesh a 256³ cabe num tempo que o artista tolera?
- [ ] o frame completo com o shader inteiro cabe em ~6 ms?
- [ ] **arrastar a luz re-acende a imagem 2D em tempo real?** ← o momento "aha" do produto
- [ ] a memória por milhão de triângulos é o que a conta previa?

Se algum destes for "não", **isso é um achado do MVP**, e ele mudou o plano — que é exatamente para isso
que o MVP existe. Um MVP que só confirma o que já se acreditava não pagou o próprio custo.

## Ordem do port

```
1. ph2d-sdf     + ph2d-mesh          (dados e algoritmos, com os gates de paridade)
2. ph2d-sculpt3d-gpu                 (os .wgsl, copiados; os pipelines, reescritos)
3. ph2d-sculpt3d                     (verbos, traço, camadas)
4. ph2d-tool-sculpt3d + panel        (a UI nativa, do zero)
5. ph2d-mesh-render                  (o shader, copiado; os passes, reescritos)
6. a doação (O1) e o objeto misto (O2)
```

Os passos 1–3 são tradução com gates; o 4 é trabalho novo; o 5 é tradução; o 6 é integração com o que a
PH2D já tem.
