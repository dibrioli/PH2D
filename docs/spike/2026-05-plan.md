# Spike de scripting — plano operacional

**Status:** Approved
**Owner:** Enio
**Início:** 2026-05-08
**Deadline:** 2026-05-29 (3 semanas calendário)
**Branch:** `spike/scripting-foundation`

## Objetivo

Validar — com medição, não opinião — a fundação da camada de scripting da PH2D, dado o princípio existencial de **LLM como único programador**. O output do spike é a decisão final entre commit ou repensar a arquitetura proposta (Luau strict via mlua + flecs-rs *ou* bevy_ecs + reset+restore hot reload + mensageria Defold-style + storage lateral + coroutines como primitiva canônica).

## Premissa não-negociável

Toda decisão técnica neste spike pesa "LLM consegue usar isso sem fricção?" no mesmo nível que "isso é correto/rápido/seguro?". API que humano tolera mas LLM tropeça é falha — não trade-off aceitável.

## O que JÁ está fechado (não medir, não rediscutir)

- Luau strict via `mlua` 0.10 com feature `luau`
- Coroutines como primitiva temporal canônica; sem async/await
- Bytecode pré-compilado no ship build
- WASM via wasmtime + Component Model (wit-bindgen) para hot path CPU-bound
- Hot reload via reset+restore (modelo Defold), não convenção `__hot__`
- Mensageria estilo Defold como mecanismo de desacoplamento
- Storage lateral para FSM/BT/Dialogue, fora do ECS, com restrições de tipo (HR-16)
- Bridge: Luau chama Rust; Rust chama WASM (single FFI boundary)
- Sandbox em dois níveis: trusted (project scripts) vs untrusted (asset scripts)
- Mensageria com hash interning, FIFO same-sender→same-target, schema opcional dev/release

## O que está em medição neste spike

- ECS canônico: flecs-rs vs bevy_ecs 0.18 (C11)
- Performance, determinismo, hot reload, GC, marshalling — números reais, não estimativa
- Fluência de LLM com a API canônica (escrita, debug, MCP)

## Critérios — 16 itens, 4 famílias

### Família A — Foundation (2)

#### C1 — Foundation roda
- **Métrica:** ECS escolhido + mlua + Luau "hello world" sobrevive 60 frames sem panic.
- **Threshold:** 0 erros, 0 panics.
- **Fixture:** `tests/spike/hello.luau`, `tests/spike/hello_runner.rs`.
- **Hardware:** Mac mini M2.
- **Aprova:** Enio.

#### C2 — Query overhead aceitável
- **Métrica:** sistema iterando 1.000 entidades com 3 componentes em Luau vs sistema equivalente em Rust nativo. Custo p99.
- **Threshold:** Luau ≤ 5× custo nativo. Acima disso, gameplay programmer (LLM) será forçado a mover lógica trivial para WASM/Rust — fricção inaceitável.
- **Fixture:** `tests/spike/query_bench.rs` (criterion-based).
- **Hardware:** Mac mini M2.
- **Sub-bullets:**
  - C2.1 — Throughput de mensageria: 100k mensagens/frame dentro de sub-budget de 1.5 ms (HR-4).

### Família B — Runtime correctness (4)

#### C3 — Coroutine timing
- **Métrica:** `ph2d.wait(0.5)` em 1.000 chamadas. Erro absoluto vs alvo.
- **Threshold:** \|actual − 0.5s\| ≤ 16.6 ms p99 (1 frame). Zero coroutines vazadas após 1.000 ciclos.
- **Fixture:** `tests/spike/coro_timing.luau`.

#### C4 — Hot reload determinístico
- **Métrica:** snapshot do `World` (postcard, blake3 hash) antes do reset+restore vs após.
- **Threshold:** 100% match em 100 ciclos. Freeze ≤ 250 ms em fixture (200 entities, 20 component types). Tasks/coroutines em voo descartadas com warning explícito.
- **Fixture:** `tests/spike/hot_reload/` (cenário inicial + script modificado).
- **Hardware:** Mac mini M2 + iPad Pro M2.

#### C9 — Replay determinístico cross-platform
- **Métrica:** fixture de 600 ticks com input log fixo. Hash blake3 do world final em 3 plataformas.
- **Threshold:** hash idêntico Linux/macOS/Windows.
- **Fixture:** `tests/spike/determinism/`.
- **Hardware:** CI matriz (GitHub Actions Linux + Mac mini M2 hospedado + Windows runner).
- **Sub-bullets:**
  - C9.1 — Storage lateral em snapshot: state_tables com profundidade 3, 50 entries, hash determinístico cross-platform após serialização sorted.

#### C10 — GC pause sob stress
- **Métrica:** GC incremental do Luau em fixture com 10.000 tabelas Lua vivas + 1.000 coroutines pendentes. Pause máximo durante 600 frames.
- **Threshold:** ≤ 1.5 ms p99 (alinhado HR-9). Acima, mover heavy logic para WASM ou reduzir alocação JS é mandatório — documentar como anti-pattern.
- **Fixture:** `tests/spike/gc_stress.luau`.
- **Hardware:** Mac mini M2 + iPad Pro M2 (GC em mobile é diferente).

### Família C — LLM-centric (5)

> **Razão da família:** PH2D é desenvolvida exclusivamente por LLM. Esta família tem o mesmo peso que correctness — não é "nice to have."

#### C5 — luau-lsp + .d.luau funcionam para casos canônicos
- **Métrica:** autocomplete em VSCode com `luau-lsp` para 5 casos canônicos: query ECS, coroutine, system, message handler, FSM.
- **Threshold:** 5/5 com tipos corretos sugeridos sem fallback `any`.
- **Fixture:** `docs/scripting/examples/spike/lsp/`.

#### C6 — MCP schema permite agente CRUD
- **Métrica:** Claude (modelo flagship vigente) via MCP cria entity, atribui component, registra system, dispara message, observa output.
- **Threshold:** 5/5 prompts canônicos resolvidos em ≤ 3 turnos (sem ajuda humana além do prompt inicial).
- **Fixture:** `docs/scripting/mcp-prompts.md` com prompts versionados.

#### C8 — LLM gera Luau idiomático (cross-vendor)
- **Métrica:** dois modelos — **Claude 4.7+** (Anthropic) e **Gemini 3.1+ Pro** (Google) — geram 5 mini-scripts canônicos: FSM básica, query ECS, coroutine de animação, mensageria pub/sub, dialogue branching.
- **Threshold:** 10/10 (5 scripts × 2 modelos) passam `luau-analyze` em strict mode + execução em fixture sem feedback humano.
- **Fixture:** `docs/scripting/examples/spike/llm-tests/`.
- **Razão para cross-vendor:** dependência de um único vendor é risco existencial quando esse vendor é seu único developer. API surface deve servir qualquer LLM forte. **Observação:** ambos os modelos escolhidos são closed-source flagship; considerar adicionar um modelo open-weights (Qwen3 ou DeepSeek atual) em revisão pós-spike como hedge contra risco vendor.

#### C15 — MCP tool fluência (cross-vendor)
- **Métrica:** dois modelos LLM (**Claude 4.7+** e **Gemini 3.1+ Pro**) executam 5 fluxos canônicos via MCP, sem ajuda humana além do prompt inicial:
  1. Criar entity + atribuir 3 components + iniciar system que opera neles.
  2. Registrar message handler + disparar message + observar processamento.
  3. Adicionar lifecycle handler (on_enter/on_exit) a uma FSM existente.
  4. Hot reload de script alterado: detectar reload, validar estado preservado.
  5. Diagnóstico: inspecionar entity por ID, listar components, ler state_table associada.
- **Threshold:** 10/10 (5 fluxos × 2 modelos).
- **Fixture:** `docs/scripting/mcp-flows/`.

#### C16 — LLM debug autonomy
- **Métrica:** fixture com 3 bugs intencionais:
  1. **Race condition:** dois systems gravam no mesmo component sem ordering explícito.
  2. **Determinism violation:** system itera `pairs()` em vez de `pairs_sorted()` em modo determinístico.
  3. **Coroutine leak:** `ph2d.cancel` chamado sem `scope_guard`, recurso GPU não-liberado.
- LLM (**Claude 4.7+** como primário, **Gemini 3.1+ Pro** como sanity check) recebe acesso a MCP tools + logs estruturados + tracing spans. Deve diagnosticar e propor fix em ≤ 5 turnos por bug.
- **Threshold:** Claude 4.7+ resolve 3/3 (bloqueante). Gemini 3.1+ Pro resolve ≥ 2/3 (não-bloqueante; abaixo disso, anotar qual gap de docs/MCP foi exposto e tratar pós-spike).
- **Razão:** se LLM não consegue debugar PH2D, o projeto não tem desenvolvedor. Esse é o critério mais existencial.
- **Fixture:** `tests/spike/debug_autonomy/`.

### Família D — Integration (5)

#### C7 — Bytecode ship build
- **Métrica:** build sem fontes `.luau` (bytecode-only). Cold start em iPad Pro M2 + size delta vs build com source.
- **Threshold:** cold start ≤ 100 ms. Size ≤ 70% da build com source.
- **Fixture:** target `cargo run --bin ship-test --features bytecode-only`.

#### C11 — ECS choice (flecs-rs vs bevy_ecs 0.18)
- **Métrica:** mesmo fixture mínimo (cena com 200 entidades, 1 hierarquia, 3 components, 2 systems, 1 observer/hook em delete) implementado em ambos. Mede:
  - LOC para cobrir o caso
  - Compile time clean + incremental
  - Binary size delta (`cargo bloat`)
  - Contagem de blocos `unsafe` em `ph2d-ecs`
  - Qualidade de stack trace em panic forçado
  - Qualidade de geração de código por LLM (3 prompts canônicos × 2 modelos = 6 amostras)
- **Threshold (flecs aceitável se TODOS):** compile time penalty ≤ 30% vs bevy_ecs; binary size penalty ≤ 15%; LLM generation quality ≥ bevy_ecs −10%; observer/hook implementação igualmente clara.
- **Senão:** bevy_ecs vence por default (mais Rust idiomático, comunidade maior, training data abundante para LLM).
- **Output:** ADR-0003-rev2 com decisão final justificada.

#### C12 — WASM marshalling budget
- **Métrica:** Luau → Rust → wasmtime call com payload primitivo (i32, f32, bool). Latência por chamada.
- **Threshold:** sub-1 µs p99 em hardware alvo. Para payload >256 bytes, usar buffer Luau zero-copy compartilhado com WASM linear memory.
- **Fixture:** `tests/spike/wasm_marshall/`.

#### C13 — Save migration end-to-end
- **Métrica:** save game em build N (formato com componente `Health { value, max }` + state_table simples). Engine atualizada para build N+1 (`Health` ganha campo `regen_rate`; state_table ganha key `last_hit_tick`). Função `migrate_v1_to_v2` escrita.
- **Threshold:** 5/5 fixtures de saves vN abrem corretamente em vN+1 sem perda de progresso.
- **Razão:** HR-14 não negocia. Storage lateral é exatamente onde migrações dão errado.
- **Fixture:** `tests/spike/migration/v1_to_v2/`.

#### C14 — Memory budget compliance
- **Métrica:** stress fixture (10.000 entities, 1.000 coroutines vivas, 200 scripts ativos, 50 WASM modules instanciados). Total memory measurement (Luau heap + WASM linear + state_table sum + ECS world + transient) em iPad Pro M2.
- **Threshold:** total < budget declarado em §12.1 do SKILL para iPad/iPhone (~1000 MB total app target).
- **Razão:** HR-13. iOS faz jetsam silencioso quando estoura — descobrir tarde é catastrófico.
- **Fixture:** `tests/spike/memory_stress/`.

## Risk register

Se semana 3 ameaça estourar, cortes aceitáveis (em ordem):

1. **C5** — substituível por verificação manual em editor (autocomplete funciona OK na inspeção visual).
2. **C12** — pode ser sub-medição em C2 (latência total já capturada).
3. **C14** — mensurável após v0.1 com fixture maior; não bloqueia início da implementação.

**Não-cortáveis** (cortar = spike falha):

- **C8, C15, C16** — se LLM não consegue gerar/usar/debugar Luau idiomático em PH2D, projeto não tem developer.
- **C13** — sem migração, save corruption mata o produto na primeira atualização.
- **C9, C10** — determinismo + GC budget são compromissos do SKILL (HR-5, HR-9).
- **C11** — sem decisão de ECS, semanas 2 e 3 são castelo de areia.

## Definition of done

Ao fim da semana 3, branch `spike/scripting-foundation` deve ter:

1. **Branch verde:** todos os critérios não-cortados passam em CI (Mac M2 + Linux + Windows runners).
2. **Relatório:** `docs/spike/2026-05-report.md` com tabela `critério | métrica | threshold | medido | passa?`. Linhas vermelhas com explicação + plano.
3. **ADR-0003-rev2:** ECS escolhido com justificativa baseada em medição.
4. **ADR-0019:** decisão final — commit ou repensar — com rationale.
5. **§11.7 do SKILL.md reescrito** refletindo decisões finais (Luau, ECS escolhido, modelos de hot reload/sandbox/mensageria conforme spike).
6. **HR-16 (storage lateral) e HR-17 (examples compilam) integradas no §9 do SKILL.**
7. **Pull request para `main`** abre revisão final por Enio.

## Sinais de falha (não negociáveis)

Se qualquer um dos abaixo ocorre, **spike falha** e arquitetura é repensada:

- Determinismo cross-platform (C9) impossível em fixture mínima.
- LLM autonomy (C16) ≤ 1/3 fixtures resolvidas.
- Save migration (C13) requer mais de 1 dia/migração para fixture trivial.
- Memory budget (C14) estoura em hardware alvo iPad antes de funcionalidades reais entrarem.
- C11 inconclusivo (medições não diferenciam): default = bevy_ecs (Rust idiomático, comunidade, LLM training data).

## Outputs do spike (contrato)

Independente de commit ou repensar:

- Tabela completa preenchida (16 critérios).
- Aprendizados documentados em ADR-0019.
- Códigos do spike preservados (mesmo que branch seja descartado).
- Atualizações do SKILL.md aplicadas refletindo decisões.

## Apêndice — fixtures canônicas para LLM (C5, C6, C8, C15)

5 mini-scripts canônicos que LLM precisa saber gerar idiomaticamente (cobertos em C8):

1. **FSM básica:** entidade muda de estado `Idle → Walk → Run` baseado em input/velocidade.
2. **Query ECS:** system itera entidades com `Position + Velocity + Sprite`, atualiza posição.
3. **Coroutine de animação:** tween de cor de sprite ao longo de 30 frames.
4. **Mensageria pub/sub:** system A envia `on_damage` para entity B; B reduz `Health`.
5. **Dialogue branching:** árvore de fala com 2 ramos baseada em flag de mundo.

Cada um é < 30 linhas. Cada um deve ser gerado por LLM sem feedback humano. Cada um é golden file no repo.
