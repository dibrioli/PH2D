# ADR-0122 — Blend Object VIVO: passos virtuais, fontes editáveis, spine editável

- **Status:** aceito (desenho; implementação faseada em curso)
- **Data:** 2026-07-14
- **Linha:** `line/Vector`
- **Supersede:** o modelo DESTRUTIVO do Blend (a `BlendSession` de `shells/desktop/src/vec_blend.rs`, que produz N paths reais). **Emenda:** ADR-0108 (o motor `ph2d-vec-*` ganha um objeto), ADR-0110/0111 (o blend é uma entidade ECS).

## Contexto

O Blend que existia era **destrutivo**: clicar "Blend" produzia N formas reais na cena, e os
escapes manuais (Rotate Match / Reverse Match) eram bugs de design — removidos (commits
anteriores desta jornada). O Enio pediu o **Blend do Illustrator de verdade**, e foi específico:

1. É **tempo-real e não-destrutivo** — ajusta-se **depois** de aplicado.
2. Não para em 12 passos — vai a **centenas**.
3. Liga **até 5 formas em sequência** ("Pick Shapes" escolhe as formas na ordem).
4. Vira **UM objeto único**, sempre editável — não N objetos.
5. Há um **PATH (spine)** unindo as formas, **editável como curva vetorial** (criar pontos,
   mover, ajustar handles).
6. As **formas-fonte continuam editáveis** — mover/escalar/rotacionar/recolorir uma **adapta** os
   intermediários. Girar a do meio adapta os ângulos das intermediárias dos dois lados.
7. Pode ser **expandido em múltiplas formas** com um botão.

A pesquisa do modelo do Illustrator (`docs/Vector Module/21_*`) confirmou item a item, e revelou o
**fato arquitetural que decide tudo**:

> Os passos intermediários são **VIRTUAIS** — *"they do not have anchor points, control handles,
> fills or strokes, but are merely an appearance generated by the blend object."* Só o **objeto
> inicial, o final e o spine** carregam geometria real.

**Isto é exatamente a costura fonte≠cozido do [ADR-0121](0121-vector-live-corners-authored-source-cooked-geometry.md).**
O blend é o `inkscape:original-d`/`d` levado ao nível do OBJETO: o autorado são as fontes + o spine;
o cozido são os passos, derivados por frame. A linha já domina esse padrão.

E a pesquisa expôs onde o Illustrator é **fraco** — e são justamente os nossos pontos fortes:

| Fraqueza do Illustrator | O que nós já temos |
|---|---|
| Correspondência **naive** (node-by-node em ordem, sem resample) → **torce** | corte na **união das âncoras** (o motor desta linha) — mantém as quinas dos dois lados, pareia 1-a-1 |
| Cor interpolada em **RGB/CMYK** device-space → passa por **cinza lamacento** | **OKLCH** perceptual (`ph2d-color`) |
| **Sem easing** (linear-only até o beta de jul/2026) | podemos ter perfil de distribuição desde o dia 1 |
| Spacing errado em **spine curvo** | podemos acertar por comprimento de arco |

## Decisão

### 1. O blend é UMA entidade ECS com um componente `VecBlend` — os passos são VIRTUAIS

Espelha o **conector** (`ph2d-ecs::VecConnector` + `shells/desktop/src/connector_live.rs`) e a
**Live Shape** (`VecShape` + `vec_shape_live.rs`): uma entidade cuja geometria é **função pura** de
outras entidades, **re-cozida por frame**.

```
VecBlend {
    sources: SmallVec<[u64; 5]>,   // VecPathId estáveis das fontes, NA ORDEM (2..=5)
    spacing: Spacing,              // Steps(u32) | Distance(f64) | SmoothColor
    orientation: Orient,           // Page (upright) | Path (tangente do spine)
    // o SPINE é a geometria da PRÓPRIA entidade do blend (o `VecPath` dela na cena),
    // editável no modo Node. Default = polilinha entre os centros das fontes.
}
```

**A referência é por `VecPathId` (u64 estável), NUNCA por `Entity::to_bits()`** — a mesma decisão
que o conector documenta (`vec_connector.rs:8-17`): o undo respawna entidades com bits novos;
`VecPathId` sobrevive ao clone (undo) e ao postcard (save). Registrado no `ComponentRegistry` ⇒
undo/save de graça.

**Os passos NÃO entram na `VecScene`.** São desenho, gerados por um passe de render que lê o
componente. É o modelo "virtual" do Illustrator, e é o que torna o blend **um objeto** (o pedido #4)
em vez de N. Consequência: os passos **não são pickáveis** individualmente (igual ao Illustrator —
o objeto é pickável, os passos não).

### 2. O SPINE é a geometria autorada da entidade; os passos são o cozido

O `VecPath` da entidade do blend guarda o **spine** — e ele é um path Bézier **comum**: editável no
modo **Node** (adicionar pontos, mover, handles), exatamente como o Enio pediu (#5). Default = a
polilinha entre os centros das fontes, **regenerada enquanto o artista não o edita** (um flag
`spine_authored`, como o conector distingue auto de fixado).

Os passos saem de posicionar cada intermediário **ao longo do spine** por comprimento de arco. Com
`Orient::Page` ficam upright; com `Orient::Path` giram para a tangente. Isto é a camada nova sobre o
motor — que hoje já interpola posição (as fontes estão em lugares diferentes, e o lerp move os
pontos): o spine default é **emergente** do lerp, e a edição do spine **re-flui** os passos.

### 3. Multi-forma = cadeia PAIRWISE (o modelo do Illustrator)

Para N fontes, o blend é `fonte[0]→fonte[1]`, `fonte[1]→fonte[2]`, … — cada par consecutivo é um
`Plan` independente (a correspondência desta linha), unidos na fonte compartilhada. Mover/girar uma
fonte do **meio** re-coza os dois segmentos adjacentes (#6) — de graça, porque cada `Plan` lê as
fontes **cozidas no mundo** a cada recook. A ordem é a de **z** (como o "Make" do Illustrator).

### 4. A cor interpola em OKLCH (onde superamos o Illustrator)

O `mix_paint` do motor passa a interpolar em **OKLCH** (via `ph2d-color`), não em RGB — sem o cinza
lamacento do device-space. É a vantagem que a pesquisa apontou, e é barata (a dep já existe no
workspace).

### 5. "Pick Shapes" é um MODO da tool (não um gesto mágico)

Um `DrawMode::PickBlend` novo (espelha o Build/Connect, cada um ~3 linhas em `tool.rs`): o cursor
coleta as formas fechadas clicadas **na ordem**, e o botão "Blend" as liga. É o análogo do Build
mode capturando faces, e do `shape_under_cursor` do conector.

### 6. Expand / Release (o "vira múltiplas formas" do Enio, #7)

- **Expand** — materializa os passos virtuais em N paths reais (o que a `BlendSession` fazia) e
  descarta o componente `VecBlend`. Espelha o `drop_shape_params` da Live Shape ("Convert to
  Curves"). As fontes persistem.
- **Release** — descarta os passos e restaura as fontes (desfaz o blend). Sem materializar nada.

## As FASES (implementação incremental, cada uma testável e smoke-ável)

| Fase | O quê | Onde |
|---|---|---|
| **1 ✅** | Retirar o Rotate/Reverse Match — correspondência 100% automática | (feito, commitado) |
| **A** | Motor **multi-forma** puro: `chain(shapes, spacing)` → passos, cadeia pairwise; cor **OKLCH** | `ph2d-vec-blend` |
| **B** | O objeto **vivo**: componente `VecBlend` + recook por frame + passe de render dos passos + skip no `settle_origins`. Spine AUTO (linha entre centros) | `ph2d-ecs` + shell |
| **C** | **Spine editável** (modo Node), **Pick Shapes** mode, painel (spacing/orientation/steps até 1000) | shell + painel |
| **D** | **Expand** / **Release** | shell |

Cada fase fecha com gate + smoke do Enio antes da próxima (a regra desta linha).

## Consequências

**Positivas:** um objeto vivo, não-destrutivo, multi-forma, com spine editável e fontes editáveis —
o Blend do Illustrator, superado nos 4 pontos onde ele é fraco. Reusa o padrão conector/Live-Shape
(undo/save de graça). O motor de correspondência (que o Enio aprovou) não muda — só ganha a camada
de cadeia + spine.

**Custos:** um passe de render novo (desenhar N formas de uma entidade — o preço de "virtual"). O
recook memoiza os `Plan`s (a correspondência é cara, ~ms; é o motivo de o `Plan` existir). O spine
como geometria-da-entidade-que-desenha-outra-coisa é uma sutileza (o path é o spine, o render são os
passos) — documentada aqui para o próximo não se surpreender.

**Descartado:** (a) **passos como entidades-filhas** — polui a hierarquia, spawn/despawn por frame,
e não é "um objeto" (o pedido explícito do Enio). (b) **passos num compound path** (subpaths de uma
entidade) — um compound path tem UM estilo, e cada passo tem cor interpolada própria. (c) o **escape
manual de correspondência** (Rotate/Reverse) — já removido; no modelo vivo o ajuste é **editar as
fontes**, que é o idioma do Illustrator e é melhor.
