# PROMPT — MVP web do PH2D Sculpt

> **Como usar:** copie deste marcador até o fim do arquivo e entregue como prompt único. Ele é
> auto-contido — não depende de nenhuma outra nota do cofre.

## 0. Quem você é e o que vai construir

Você vai construir o **PH2D Sculpt Web MVP**: um aplicativo de **escultura 3D** que roda no navegador,
escrito em **TypeScript + WebGPU (WGSL)**, sem framework.

Ele é um **protótipo descartável com um núcleo permanente**: os *shaders WGSL* e a *estrutura dos
algoritmos* serão portados **verbatim** para Rust + `wgpu` na engine PH2D. O DOM, o TypeScript de cola e
o empacotamento são descartáveis. Escreva com essa assimetria em mente o tempo todo.

**Referência maior de experiência de uso: [Nomad Sculpt](https://nomadsculpt.com).** A referência de
*capacidade* é o ZBrush. A meta explícita é: **o poder do ZBrush com a facilidade do Nomad.**

**Precedente legível:** [SculptGL](https://github.com/stephomi/sculptgl) — mesmo autor do Nomad,
**licença MIT**, WebGL, com subdivisão dinâmica, decimação e uniformização. Você **pode** ler e adaptar
o código dele. Você **não pode** ler ou copiar código do Blender (GPL) — dele, apenas comportamento
observável.

### As duas razões de este app existir

O MVP tem de provar, no navegador, as duas coisas que o produto final precisa entregar:

- **O1 — Escultura que ilumina pintura 2D.** A forma doa `normal · profundidade · AO · cavidade ·
  material` a uma imagem 2D, que é então iluminada pelo mesmo rig de luzes da forma.
- **O2 — Forma 3D por baixo de um sprite.** Um sprite 2D com uma malha 3D "filha" que lhe empresta o
  shader; o resultado roda como 2D com iluminação 3D.

Se o app esculpir lindamente e não provar O1 e O2, **ele falhou**.

## 1. Leis inegociáveis

Estas onze leis valem sobre qualquer preferência de estilo. Cada uma existe porque o projeto PH2D já
pagou por violá-la.

1. **GPU-residente.** A malha vive em `GPUBuffer`. Nenhum *readback* por frame. Leitura de volta só em
   exportação, salvamento e operações de topologia que rodam sob comando.
2. **WGSL é o entregável.** Todo shader deve compilar sem modificação sob `naga` (o compilador do
   `wgpu`). Proibido usar extensão WebGPU sem equivalente documentado em `wgpu 28`.
3. **A lei do traço.** O efeito de um traço é função do **CAMINHO**, nunca da densidade de amostragem do
   ponteiro. Congele a base no *pen-down*; acumule por **envelope** (`max`), não por soma. (Detalhe na
   §5.1. Exceção explícita: verbos de deslocamento, §5.4.)
4. **Uma pergunta, uma porta.** Qualquer número que a interface mostra e o motor usa é calculado por
   **uma** função. Duas cópias divergem, e a divergência é sempre descoberta tarde.
5. **Meça antes de limitar.** Nenhuma constante `MAX_*`, teto de resolução ou "por segurança" entra no
   código sem a tabela de medição ao lado dela, no comentário. Um limite legítimo diz **de que recurso
   ele é**.
6. **Determinismo barato.** Reduções em ordem fixa. **Sem atômicos em `f32`.** Prefira *gather* a
   *scatter*. Onde precisar somar contribuições por vértice, use adjacência CSR e some na ordem do
   índice.
7. **Sem botão morto.** Todo controle pintado faz algo. Se um controle não se aplica ao estado atual,
   ele **não é pintado** — nunca pintado-e-inerte.
8. **Sem conceito exposto sem necessidade.** O artista 2D nunca deve ler as palavras *topologia*,
   *isosuperfície*, *voxel* ou *manifold* na interface. Ele lê *"a malha se adapta"*, *"Remesh"*,
   *"Resolução"*.
9. **Toda operação é desfazível, em um passo por gesto.** Um arrasto de traço = um passo de undo.
10. **Nada some em silêncio.** Se uma operação descarta geometria, atributos ou detalhe, ela **avisa**.
11. **Sem dependências desnecessárias.** Matemática, math de matriz e I/O escritos à mão (são poucas
    centenas de linhas e viram o port em Rust). Bibliotecas só para o que for genuinamente grande.

## 3. Modelo de dados

### 3.1 A malha (a representação primária)

```ts
interface MeshBuffers {
  positions: GPUBuffer;   // vec3<f32> × V   (posição corrente)
  base:      GPUBuffer;   // vec3<f32> × V   (posição congelada no pen-down)
  normals:   GPUBuffer;   // vec3<f32> × V
  colors:    GPUBuffer;   // vec4<f32> × V   (cor por vértice, linear)
  masks:     GPUBuffer;   // f32       × V   (0 = livre, 1 = protegido)
  material:  GPUBuffer;   // vec4<f32> × V   (rugosidade, metalicidade, sss, espessura)
  accum:     GPUBuffer;   // f32       × V   (acumulador do traço corrente)
  indices:   GPUBuffer;   // u32       × 3T
}
```

A CPU mantém cópia-sombra **apenas** para topologia, exportação e salvamento — nunca para desenhar.

### 3.2 Adjacência CSR (vértice → faces)

```ts
interface Adjacency {
  offsets: GPUBuffer;  // u32 × (V+1)
  faces:   GPUBuffer;  // u32 × soma(grau)
}
```

Reconstruída **só** quando a topologia muda. Usada para recomputar normais e curvatura por *gather*
(sem atômicos ⇒ determinístico, lei 6).

### 3.3 Grade espacial uniforme (na GPU)

Construída por três passes — **`count → scan → scatter`** — sobre a AABB da malha, com célula ≈ 2× o
comprimento médio de aresta.

```
cellCount[]  → contagem por célula        (compute, atomicAdd em u32 — permitido)
cellStart[]  → soma de prefixo exclusiva  (compute, scan Blelloch)
cellItems[]  → índices de vértice         (compute, scatter)
```

Reconstruída quando a topologia muda ou quando o *bounding box* cresce além de uma margem. Serve
consulta de pincel, voxelização e colisão.

> ⚠️ O `scan` é **o mesmo primitivo** que a PH2D já tem em `ph2d-gpu-cook::scan`. Escreva-o aqui com a
> mesma estrutura (Blelloch de duas fases, workgroup + agregação) para o port ser troca de arquivo.

### 3.4 O campo (SDF) — auxiliar, nunca display

```ts
interface SdfField {
  brickTable: GPUBuffer;  // page table esparsa
  bricks:     GPUBuffer;  // 8³ f16 por brick, banda estreita
  gridDim:    [number, number, number];
  cellSize:   number;
}
```

Usado **apenas** por: voxel remesh, primitivas/booleanas ao vivo, Skeleton, e assamento de AO/espessura.

### 3.5 Camadas de escultura

```ts
interface SculptLayer {
  id: string;
  name: string;
  visible: boolean;
  weight: number;           // 0..1, editável DEPOIS de esculpido
  deltas: GPUBuffer;        // esparso: (u32 index, vec3<f32> delta)[]
  count: number;
}
```

A posição final é `base_layer0 + Σ (layer_i.delta × layer_i.weight)`. É a feature não-destrutiva que o
Nomad tem e que faz o artista confiar na ferramenta.

## 4. Arquitetura de módulos

Dependências em **uma direção só**, de cima para baixo. Nenhum módulo abaixo conhece o de cima.

```
src/
  app/            main.ts, loop, estado global      → descartável
  ui/             painéis DOM, sliders, curva       → descartável
  input/          ponteiro, caneta, toque, atalhos  → descartável
  scene/          objetos, hierarquia, câmera       → porta parcial
  sculpt/         traço, verbos, máscara, camadas   → PORTA (ph2d-sculpt3d)
  mesh/           buffers, adjacência, grade        → PORTA (ph2d-mesh)
  topo/           remesh, dyntopo, multires, QEM    → PORTA (ph2d-mesh)
  field/          SDF esparso, surface nets         → PORTA (ph2d-sdf)
  prims/          primitivas paramétricas, skeleton → PORTA (ph2d-sculpt3d)
  render/         passes, G-buffer, post            → PORTA (ph2d-mesh-render)
```

## 5. O motor de escultura

### 5.1 O modelo de traço (a lei 3, concreta)

```
pen-down:
    base ← positions            (copy buffer, GPU-side)
    accum ← 0
    abrir passo de undo

pointer-move:
    emitir dabs ao longo do caminho, espaçados por `spacing × raio`
    para cada dab: aplicar kernel (§5.2)
    recomputar normais da região afetada

pen-up:
    fechar o passo de undo (só a janela de vértices tocados)
    descartar accum
```

**Um dab** é:

```ts
interface Dab {
  center: vec3;       // em espaço de objeto
  radius: number;
  strength: number;   // 0..1
  pressure: number;   // 0..1 da caneta
  dir: vec3;          // direção do traço (de CENTROS consecutivos, não de média suavizada)
  normal: vec3;       // normal da superfície sob o cursor, no pen-down do segmento
  delta: vec3;        // deslocamento do cursor, para verbos de movimento
  plane?: { point: vec3, normal: vec3 };  // ajuste por mínimos quadrados, §5.3
}
```

> ⚠️ **`dir` vem da diferença entre centros de dabs consecutivos.** Uma média exponencial suavizada
> atrasa até 52° em pincel grande — medido na PH2D 2D, e o sintoma que o artista relata é *"o rake não
> gira"*. Não repita esse erro.

### 5.2 O kernel do pincel (compute)

Um único shader, dois passes:

```wgsl
// PASSE 1 — acumular influência (envelope)
@compute @workgroup_size(64)
fn accumulate(@builtin(global_invocation_id) gid: vec3<u32>) {
  let v = gid.x;
  if (v >= uniforms.vertexCount) { return; }

  let p = base[v];
  let d = distance(p, dab.center);
  if (d > dab.radius) { return; }

  let t = falloff(d / dab.radius, uniforms.falloffKind);
  let w = t * dab.strength * dab.pressure * (1.0 - masks[v]);

  accum[v] = max(accum[v], w);        // ← A LEI. nunca `accum[v] += w`
}

// PASSE 2 — aplicar o verbo
@compute @workgroup_size(64)
fn apply(@builtin(global_invocation_id) gid: vec3<u32>) {
  let v = gid.x;
  if (v >= uniforms.vertexCount) { return; }
  let a = accum[v];
  if (a <= 0.0) { return; }

  let target = verbTarget(v);          // switch resolvido por const de permutação
  positions[v] = mix(base[v], target, a);
}
```

**Otimização obrigatória:** o passe 1 não itera todos os vértices — ele itera **as células da grade que
a esfera do dab toca** (§3.3), em despacho indireto. A versão acima é a referência legível; a versão de
produto usa a grade. Escreva as duas e mantenha um gate de paridade entre elas.

### 5.3 O ajuste de plano

Para os verbos da família de plano, ajuste um plano por **mínimos quadrados sobre os vértices da
pegada**, ponderado pelo falloff:

```
centroide c = Σ(w·p) / Σw
covariância M = Σ w·(p−c)(p−c)ᵀ
normal = autovetor de menor autovalor de M
```

⚠️ **O plano é INCLINADO, nunca horizontal.** Um ajuste horizontal *cava uma cratera na encosta* em vez
de achatá-la. (Erro pago e corrigido no Painter 2D da PH2D.)

Implementação: redução em duas etapas na GPU (por workgroup, depois global), **em ordem fixa**.

### 5.4 Os verbos

Implemente **todos**. Cada um é uma função `verbTarget` numa permutação do mesmo shader.

#### Família A — desloca ao longo da normal

| Verbo | Alvo | Parâmetros próprios |
|---|---|---|
| `Draw` | `base + n·depth` | profundidade, ±, "normal da superfície" × "normal do dab" |
| `DrawSharp` | idem, falloff `pow4` | — |
| `Inflate` | `base + n_v·depth` (normal do vértice) | — |
| `Blob` | inflate com peso `a²` | — |
| `Layer` | `base + n·depth`, **limitado** a `depth` | altura, ± |

#### Família B — ajusta a um plano

| Verbo | Alvo | Sinal |
|---|---|---|
| `Flatten` | plano ajustado | ambos |
| `Fill` | plano ajustado | só cima |
| `Scrape` | plano ajustado | só baixo |
| `Clay` | plano + offset positivo | ambos |
| `ClayStrips` | idem, dab **quadrado** (alpha retangular) | ambos |
| `TrimDynamic` | plano do dab, projeção dura | ambos |

#### Família C — suaviza / enrijece

| Verbo | Alvo |
|---|---|
| `Smooth` | laplaciano da vizinhança (via CSR); ofereça também HC-Laplacian, que encolhe menos |
| `Sharpen` | o mesmo com sinal trocado |
| `Pinch` | move tangencialmente para o centro do dab |
| `Magnify` | move tangencialmente para fora |
| `Crease` | `Pinch` + deslocamento negativo |

#### Família D — move matéria (⚠️ NÃO usa envelope)

Estes **compõem por natureza** — puxar duas vezes puxa mais longe. Use **composição de mapas**:

```
disp_novo(p) = v(p) + disp_velho(p − v(p))
```

| Verbo | Comportamento |
|---|---|
| `Move` | translada o miolo pelo `delta` do cursor |
| `SnakeHook` | `Move` que arrasta e estica (pede dyntopo para não rasgar) |
| `ElasticDeform` | queda longa e suave (Kelvinlets) |
| `Nudge` | move tangencialmente, na direção do traço |
| `Twist` | rotaciona o miolo em torno do eixo da câmera |

#### Família E — não move geometria

| Verbo | Escreve em |
|---|---|
| `Mask` | `masks[v]` (e todos os outros o respeitam via `1 − mask`) |
| `Paint` | `colors[v]` |
| `MaterialPaint` | `material[v]` (rugosidade / metalicidade / SSS) |
| `Simplify` | decimação local (requer dyntopo ligado) |

### 5.5 Falloffs

Uma tabela compartilhada, **uma porta**:
`Smooth · Sphere · Sharper(pow4) · Constant · Root · Curva customizada`.

A curva customizada é uma spline editável (ver §13.4). Amostre-a para uma LUT de 256 entradas e envie
como textura 1D — nunca avalie a spline no shader.

### 5.6 Simetria

- espelho por eixo `X`/`Y`/`Z`, combináveis
- **radial** de `N` em torno de um eixo
- espelho **local** (eixo do objeto) × **mundo**

⚠️ **A simetria é aplicada na LISTA DE DABS, num ponto único** — nunca dentro de cada verbo. É isso que
faz um verbo novo herdar simetria de graça.

### 5.7 Alphas / stencils

Textura de alpha projetada no frame do dab (`tangente × bitangente × normal`), multiplicando `w`.
Opção `rake`: o frame acompanha `dab.dir`.

## 6. Topologia

> **Regra de UX (lei 8):** a aba se chama **Topologia** e tem quatro controles. Nada mais.

### 6.1 Voxel remesh (o cavalo de batalha)

```
malha → SDF        winding number generalizado ou varredura rápida, na grade da §3.4
SDF   → malha      surface nets (dual contouring simples), em compute, por brick
atributos          re-projetados por vizinho mais próximo (cor, máscara, material)
```

⚠️ **Os atributos TÊM de viajar.** Remesh que perde a cor por vértice é remesh que o artista aprende a
temer.

Parâmetros: `resolução (voxels na maior dimensão)`, `manter atributos`, `preservar quinas`.

### 6.2 Topologia dinâmica (opt-in, **nunca** padrão)

- `split` de aresta com comprimento > `alvo × 1.5`
- `collapse` de aresta com comprimento < `alvo × 0.5`
- só na vizinhança do dab, uma vez por segmento de traço

Na GPU isso é alocação + **compactação** de buffers — use o mesmo `scan` da §3.3. **Rota de escape
permitida:** se a versão GPU não fechar no tempo do MVP, implemente em CPU e documente o custo. Não
bloqueie o MVP nisso.

⚠️ Os próprios desenvolvedores do Blender publicaram que dyntopo *"é bem mais lento e come muito mais
memória"* que malha comum ou multires. É por isso que ele é opt-in.

### 6.3 Multiresolução

- nível 0 = malha base; cada nível = subdivisão Catmull-Clark
- detalhe de nível alto guardado como **deslocamento** relativo ao nível abaixo
- esculpir em nível baixo move a forma **preservando** o detalhe de cima

### 6.4 Decimação

QEM (*quadric error metrics*), com preservação de fronteira e de atributos. Dois consumidores: LOD de
exportação e o verbo `Simplify`.

### 6.5 Booleanas

Via campo: união / subtração / interseção, com `smin` opcional (fusão suave, slider `Fusão`).
Booleana exata de malha **não** entra no MVP — documente a ausência.

## 11. O renderizador

### 11.1 Passes

```
depth prepass → G-buffer → iluminação → post
```

### 11.2 Layout do G-buffer (exato)

| Alvo | Formato | Conteúdo |
|---|---|---|
| RT0 | `rgba16float` | normal octaédrica (RG) · rugosidade (B) · metalicidade (A) |
| RT1 | `rgba8unorm` | albedo (RGB) · id de material (A) |
| RT2 | `rgba8unorm` | espessura/SSS (R) · cavidade (G) · AO (B) · máscara (A) |
| — | `depth32float` | profundidade |

### 11.3 Iluminação

Implemente **tudo isto**, cada item pela via pré-integrada:

1. **Cook-Torrance GGX** — `D` Trowbridge-Reitz, `V` Smith *height-correlated*, `F` Schlick.
2. **Compensação de multiscatter** (aproximação de Fdez-Agüera, ~4 linhas, usa a LUT do split-sum).
   ⚠️ Sem ela, metal áspero fica cinza-sujo. É a diferença mais barata entre "jogo de 2010" e "Unreal".
3. **SSS pré-integrado** (Penner): LUT 2D indexada por `(N·L, curvatura)`. **Uma amostra de textura.**
4. **Transmitância**: `exp(−espessura × coeficiente)` para contraluz, com espessura assada por vértice.
5. **AO**: assado por vértice (cone tracing contra o SDF) + GTAO em tela como opção.
6. **Cavity**: da curvatura por vértice — côncavo escurece, convexo clareia. Dois sliders (`Cavity`,
   `Edge Wear`).
7. **IBL**: difuso por harmônicos esféricos de ordem 2 (9 coeficientes, sem textura) + especular por
   mapa pré-filtrado × LUT BRDF (split-sum).
8. **Luzes analíticas**: 1 direcional com CSM + até 8 pontuais/spot.
9. **Matcap**: modo de escultura, uma amostra de textura. **É o modo padrão ao esculpir.**

### 11.4 Post

`bloom → tonemap (AgX) → FXAA → vinheta/sharpen`

### 11.5 Arquitetura do shader

**Um WGSL uber**, com permutações resolvidas na criação do pipeline via constantes
(`SSS on/off`, `IBL on/off`, `CSM on/off`, `MATCAP`). Não `if` em runtime; não dez arquivos.

## 15. Undo

```ts
interface UndoStep {
  layerId: string;
  indices: Uint32Array;     // a JANELA: só os vértices tocados
  before:  Float32Array;    // 3 × indices.length
  after:   Float32Array;
  topology?: MeshSnapshot;  // só quando a topologia mudou
}
```

**Leis:**

- a **janela vem de quem escreve** — o kernel do pincel já sabe quais vértices tocou; nunca redescubra
  varrendo a malha;
- teto do histórico em **BYTES**, não em contagem de passos (`orçamento = f(tamanho da malha)`);
- operação de topologia guarda um instantâneo completo e **conta como um passo caro** no orçamento.

> Estas três regras vêm de dois bugs reais já pagos na PH2D (memória do editor de áudio; histórico do
> Painter, que chegou a reter 1.627 MB por guardar o documento inteiro por traço).

## 17. Performance — sondas, não caps

⚠️ **Lei 5.** Nenhum teto de resolução, contagem de vértices ou tamanho de brick entra no código sem a
tabela ao lado. Construa as sondas **desde o começo**, não no fim.

Uma tela `?probe=1` que roda e **imprime uma tabela**:

| Sonda | Mede |
|---|---|
| `probe_brush` | ms por dab × vértices afetados (10³, 10⁴, 10⁵, 10⁶) |
| `probe_normals` | ms para recomputar normais de N vértices |
| `probe_grid` | ms para reconstruir a grade espacial |
| `probe_remesh` | ms de voxel remesh por resolução (64³, 128³, 256³, 512³) |
| `probe_render` | ms do frame por resolução e nº de luzes |
| `probe_memory` | MB residentes por contagem de triângulos |
| `probe_stroke_e2e` | ms do `pointerdown` até o pixel na tela |

**Regra de redutor:** use a **mediana** de N repetições, descartando a primeira (compilação de pipeline
e *first-touch* de memória distorcem a primeira). Reporte `min`, `mediana` e `max` — nunca só a média.

## 18. Gates (mesmo num MVP)

Um MVP sem verificação vira um protótipo que mente. Implemente:

1. **Paridade CPU × GPU** — uma implementação de referência em TypeScript de cada verbo, comparada com
   o resultado da GPU dentro de um épsilon documentado.
2. **Paridade grade × força-bruta** — o kernel com consulta de grade dá o mesmo resultado do kernel que
   varre todos os vértices.
3. **Independência de espaçamento** — o mesmo caminho traçado com 1 px e com 4 px de espaçamento produz
   **o mesmo** resultado (é a lei 3, executável).
4. **Idempotência de re-stamp** — reaplicar o mesmo traço não intensifica.
5. **Ida e volta de arquivo** — salvar, carregar, comparar byte a byte.
6. **Remesh preserva atributos** — cor e máscara sobrevivem, dentro de tolerância.
7. **Undo/redo** — N operações aleatórias, desfazer tudo, comparar com o estado inicial.
8. **Validação WGSL** — todo shader passa por validação na inicialização e falha alto se não passar.

## 20. Contrato de porte para Rust + wgpu

O que é **permanente** (escreva com carinho, será lido por anos):

| Permanente | Vira |
|---|---|
| todo `src/shaders/*.wgsl` | os mesmos arquivos, em `ph2d-sculpt3d-gpu` e `ph2d-mesh-render` |
| layouts de buffer e `struct` de uniform | `#[repr(C)]` + `bytemuck::Pod` |
| a matemática de cada verbo | `ph2d-sculpt3d` |
| a lei do traço e a tabela de falloff | idem |
| os algoritmos de topologia | `ph2d-mesh` |
| o formato de arquivo | leitor em Rust, tradução direta |
| os gates da §18 | testes Rust, mesmos oráculos |

O que é **descartável**: `app/`, `ui/`, `input/`, o empacotador, o CSS.

**Regras que protegem o porte:**

1. Nenhuma extensão WebGPU sem equivalente em `wgpu 28`.
2. Nenhum `f32` atômico (não existe em WGSL padrão, e o determinismo o proíbe — lei 6).
3. Todo `struct` de uniform com alinhamento explícito e comentado (`std140`/`std430` são armadilha
   silenciosa entre JS e Rust).
4. Nenhuma dependência do layout de memória do JavaScript.
5. Cada arquivo `.wgsl` abre com um comentário dizendo **qual crate Rust vai hospedá-lo**.

## 22. Critérios de aceite
