# Módulo removível e mapa de crates

> Exigência do Enio: *"vamos implementar em módulo facilmente removível do projeto para o caso de não
> dar certo."* Esta nota é o contrato que torna isso verdade — e ele tem de ser escrito **antes** da
> primeira linha de código, porque acoplamento não se remove depois.

## O mapa de crates

Todas **novas**, todas drop-crate (§0.1 do `CLAUDE.md`), nenhuma na fundação:

| Crate | Papel | Depende de | Pode ser apagada? |
|---|---|---|---|
| `ph2d-sdf` *(já existe, vazia)* | campo esparso em bricks, banda estreita, voxelização, surface nets | leaf | ✅ |
| `ph2d-mesh` | malha residente: buffers, adjacência CSR, grade espacial, atributos | leaf | ✅ |
| `ph2d-sculpt3d` | os verbos, o modelo de traço, máscara, simetria, camadas de escultura | `ph2d-mesh`, `ph2d-sdf` | ✅ |
| `ph2d-sculpt3d-gpu` | WGSL: pincel, normais, remesh, extração, G-buffer | `ph2d-gpu`, `ph2d-mesh` | ✅ |
| `ph2d-mesh-render` | o shader de runtime (PBR+SSS+AO+Cavity), passes, post | `ph2d-render`, `ph2d-gpu` | ✅ |
| `ph2d-tool-sculpt3d` | a `Tool` do editor | contrato existente | ✅ |
| `ph2d-panel-sculpt3d` | o painel docado | `ph2d-panel-*` | ✅ |
| `ph2d-light` *(já existe, vazia)* | rig de lâmpadas compartilhado por tinta e forma | `ph2d-render` | ⚠️ **não** — vira fundação depois que o Painter passar a usá-la |

⚠️ **`ph2d-light` é a única exceção, e é deliberada.** Ela existe para que *um rig ilumine tinta e forma*;
depois que o Painter passar por ela, arrancá-la quebraria o Painter. **Mitigação:** ela é promovida
**apenas na wave da doação**, e até lá o módulo 3D usa o rig do impasto como está. Se o módulo for
cancelado antes dessa wave, `ph2d-light` volta a ser uma crate vazia sem dependentes.

## A feature flag única

```toml
# shells/desktop/Cargo.toml
[features]
default = ["…"]
sculpt3d = [
    "dep:ph2d-tool-sculpt3d",
    "dep:ph2d-panel-sculpt3d",
    "dep:ph2d-mesh-render",
]
```

**Regras que a flag tem de obedecer** (cada uma vira um gate):

1. **Com a flag desligada, nada do módulo compila.** Todas as dependências são `optional = true`.
2. **Nenhum `use` de crate do módulo fora de um `#[cfg(feature = "sculpt3d")]`.**
3. **Nenhum componente ECS do módulo é registrado** com a flag off — logo o `ComponentRegistry` não muda
   de contagem, logo projetos salvos sem o módulo abrem sem ele.
4. **Nenhum id de widget, token de tema ou chave i18n** do módulo existe com a flag off (a lei do
   *botão morto*: id registrado que nunca pinta apodrece).
5. **O caminho da tinta sai byte-idêntico** com a flag on ou off — gate de *fingerprint*, no molde do
   `fade_fingerprint` da timeline.

## As três costuras que tocam código existente

Só três, e as três são **aditivas com default neutro** — o padrão que a casa já usou quatro vezes
(canal novo é side-metadata no registry, nunca contrato):

| # | Onde | O que muda | Com a flag off |
|---|---|---|---|
| S1 | `ph2d-render` | o passe de luz aceita normal de duas fontes | consome só o plano do impasto — **byte-idêntico** |
| S2 | `ph2d-tool-painter::LayerKind` | variant `Sculpt3d(...)` **apendado** | variant nunca construído; índices postcard não se movem |
| S3 | `ph2d-ecs` | componentes `Mesh3D` / `MeshShading`, registrados sob a flag | não registrados ⇒ contagem do registry intacta |

⚠️ **`PROJECT_SCHEMA` bumpa uma vez**, pelo caminho **inverso**: arquivo salvo *com* o módulo não abre
em binário *sem* ele. Mitigação: o asset da escultura viaja como **blob que carrega a própria versão**
dentro do `ProjectFile` — o precedente do `TimelineDoc` —, então o módulo pode evoluir muitas waves sem
bumpar `PROJECT_SCHEMA` de novo.

## Procedimento de remoção (o teste real da promessa)

Se o módulo não vingar, a remoção é isto e nada mais:

```bash
# 1. apagar as crates do módulo
rm -rf crates/ph2d-{mesh,sculpt3d,sculpt3d-gpu,mesh-render,tool-sculpt3d,panel-sculpt3d}
#    (ph2d-sdf e ph2d-light voltam a ser crates vazias, como já eram)

# 2. remover a feature e as 3 costuras
#    - shells/desktop/Cargo.toml: a feature `sculpt3d`
#    - S1: o segundo produtor de normal no passe de luz
#    - S2: o variant Sculpt3d de LayerKind
#    - S3: o registro dos 2 componentes

# 3. conferir
cargo check --workspace && ./scripts/ship.sh
```

**Gate que mantém a promessa honesta:** um teste de arquitetura que varre o workspace e falha se
qualquer arquivo **fora** das crates do módulo mencionar um símbolo do módulo sem `#[cfg(feature)]`.
Sem esse gate, a promessa vira opinião no segundo mês.

## Por que isso não é paranoia

O repositório já removeu módulos inteiros duas vezes — a aquarela/fluid
([ADR-0096](../../architecture/decisions/0096-remove-watercolor-fluid-pivot-mixer-brush.md), 1 crate + sessões GPU)
e a pintura inteira ([ADR-0099](../../architecture/decisions/0099-remove-painting-brush-engine-preserve-layers-effects.md), **8 crates**).
Nos dois casos a remoção foi limpa **porque o isolamento tinha sido projetado antes**. Este é o mesmo
seguro, contratado na mesma seguradora.
