# PH2D Wet Paint — provenance & process record

PH2D Wet Paint was produced by a deliberate two-role ("clean-room") process, recorded here.

## Roles

- **Specification author** (session of 2026-07-02): studied watercolor-simulation behavior — the
  published literature (Stam, *Stable Fluids*, SIGGRAPH 1999; Curtis et al., *Computer-Generated
  Watercolor*, SIGGRAPH 1997; Kubelka–Munk pigment theory) and the externally observable behavior
  of existing watercolor applications — and wrote `SPEC.md`: a purely behavioral specification
  (data model, update rules, cadences, boundary conditions, calibration parameters, acceptance
  tests) in its own words and notation. The spec contains no third-party source code, no
  third-party identifiers, and no citations into any third-party implementation.
- **Implementer** (separate agent session, fresh context): received **only `SPEC.md`** and wrote
  every line of code in this folder from it. The implementer had no access to any third-party
  painting application's source code, to any prior in-repo watercolor experiment, or to any notes
  about them, and was explicitly instructed to ignore any such context and to choose its own
  architecture and naming.
- **Verifier** (specification author): validated the result behaviorally — the Node smoke tests
  in `test/` plus interactive comparison of the painted output — without transplanting code.

## Why this process

Algorithms, physical models, and calibration values are not subject to copyright; specific
expression (code) is. Keeping the roles separated ensures this implementation is an independent
expression of well-known simulation techniques. The quantitative calibration targets in `SPEC.md`
(paper-texture statistics, solver gains, cadences) are functional parameters characterizing the
intended *behavior* of the product.

## Assets

All assets are procedural (paper tooth, bristle texture, UI) — generated by the code in this
folder from deterministic seeds. No third-party images, fonts, or data files are included.
